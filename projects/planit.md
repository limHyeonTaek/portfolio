## 역할

- 페이지 설계·구현: 홈, 여행 목록·상세, 여행 랜딩 시리즈, 링크 허브·월 납부금 플로우, 로그인·마이페이지, 휴대폰·렌탈·인터넷·보험 페이지
- 어드민 견적 도구: 견적번호 발급, 견적서 전용 주소, 고객 일정표 짧은 주소·사진 자동 삽입·미리보기
- 피그마 시안 코드화: 웹 1440·모바일 390 두 벌, 스크롤 모션 포함
- 상담 접수 폼과 전산 연동(접수 API 는 전산 백엔드가 제공)
- 계측: 메타 픽셀, GA4, Clarity, 네이버 분석, 유입 경로 수집
- 배포·인프라: GitHub Actions(OIDC) → S3 + CloudFront, CloudFormation

## 핵심 기능

- **홈 랜딩**과 **여행 목록·상세**
  - 홈 「10월 특가여행」 섹션을 「가성비 동남아」 레일로 바꿨습니다(2026-11-04).
  - 여행 탭을 전체 상품 목록 + 카테고리 칩(초가성비·가성비 포함)으로 단순화하고, 같은 여행지 상품은 한 카드로 묶어 옵션으로 고르게 했습니다.
  - 상품은 전산의 상품 대량 등록·정리 API 로 새 목록(28개 상품)에 맞춰 한 번에 교체했습니다(2026-10-29).
- **여행 랜딩 시리즈**: 피그마 시안을 웹 1440·모바일 390 두 벌로 1:1 코드화하고 스크롤 모션을 붙였습니다.
  - LP-01 원페이지 상담, LP-02 후불여행, LP-03 동남아 월 가격, LP-04 신혼여행, LP-05 효도여행, LP-06 우정여행, LP-07 가족여행, 보험 B2B 시상여행(피그마 LP-08)
  - 카테고리별 정적 경로 `/travel/lp/<slug>/` 11개
  - LP-07 가족여행: 가족에게 보내는 공유 카드(카카오톡 공유)와 인원 계산기(3·4·5인 + 직접 입력, 1인 월 금액 × 인원)
  - LP-05 효도여행(2026-10-27): 형제 수 계산기(혼자·2·3·4명, 부모님 2인 월 금액을 형제 수로 나눔). 표지는 테마 페이지와 같은 영상을 씁니다.
  - 보험 B2B 시상여행(2026-10-27, `/travel/lp/incentive/`): 시안의 신청 칸(이름·직책, 소속, 인원, 1인 예산)이 개인용 공용 폼과 달라 전용 B2B 신청서를 랜딩 안에 따로 만들고, 같은 접수 API 로 보냅니다. 「본부·지점에 링크 공유하기」는 카카오톡 리스트형 메시지입니다.
  - LP-10 렌탈+동남아(`/travel/lp/rental-sea/`) — 진행 중(2026-11-06): 피그마 시안 코드화, 제품 사진이 끝없이 흐르는 띠, 렌탈 상담 폼과 제3자 제공 동의
- **링크 허브(LP-08)**: 인스타그램 캐러셀에서 들어오는 [`/link/`](https://플랜잇.com/link/). 버튼마다 UTM 을 붙여 어느 버튼으로 들어온 유입인지 전산에서 구분합니다.
- **월 납부금 플로우(LP-08)**: [`/link/monthly/`](https://플랜잇.com/link/monthly/) 01 여행지 → 02 인원·시기 → 03 결과·카카오톡 공유 → 04 상담 신청. 상담 신청은 여행 랜딩 폼과 같은 규칙·접수 API 를 쓰고, 앞 단계에서 고른 값을 미리 채웁니다.
- **견적 일정표**: 견적번호마다 고객에게 보내는 일정표 페이지입니다(검색 노출 제외). 처음에는 공용 화면 틀 하나와 견적별 데이터 모듈로 빌드 때 구웠고, 지금은 어드민에서 번호를 발급하면 일정 스냅샷이 서버에 저장되고 공용 화면이 번호로 읽어 그립니다.
  - 짧은 주소 `/q/번호`(2026-11-05): CloudFront 함수가 공용 화면을 돌려주고 주소창은 `/q/번호` 그대로 둡니다. 구운 번호는 구운 일정, 새 번호는 서버 스냅샷을 그립니다.
  - 견적서 만들기 전용 주소 `/admin/quote/`(2026-11-05): 어드민 탭 안의 하위 탭에서 떼어 내고, 어드민 로그인 단계를 재사용 컴포넌트로 빼서 함께 씁니다.
  - 모두투어 사진 자동 삽입(2026-11-06): 표지 1장 · 일차별 관광지 최대 3장 · 호텔 1장. 선택관광·식사 항목과 외부 DB 사진은 넣지 않고, 어드민에서 표지를 바꾸거나 사진을 끌 수 있습니다. 번호 발급 때 스냅샷에 저장하고, 공개 화면은 사진을 referrer 없이 불러옵니다.
  - 「일정표 미리보기」(2026-11-06): 번호를 발급하지 않고 지금 입력한 상태를 고객 화면 그대로 새 탭에서 봅니다.
  - 견적서 화면과 계산 규칙(계약금 먼저 차감, 납부 방식 추가)은 공동 작업자가 맡았고, 저는 번호 발급·주소·사진·미리보기와 운영 승격을 맡았습니다.
- **소셜 로그인(네이버·카카오)**(2026-10-28): 로그인 화면, 제공자별 콜백 페이지, 마이페이지(로그아웃·회원 탈퇴)를 만들고 개인정보처리방침·이용약관을 개정했습니다. 로그인·세션은 전산 백엔드 API 가 맡습니다.
- **휴대폰·인터넷 새 화면 운영 전환**(2026-11-05): 공동 작업자가 만든 새 화면(인터넷은 첫 화면·직접 선택·맞춤 추천·지원금 안내 4개)을 빌드 플래그 하나가 함께 켜던 것을 휴대폰·인터넷 둘로 나눠, 백엔드가 준비된 쪽부터 운영에 켰습니다.
- **상담 접수 폼**: 생년월일·납부 방식 등 전 항목 필수, 개인정보 동의 문구는 버전으로 관리, 입력 칸 초점 표시는 칸 테두리 한 겹으로 통일
- **휴대폰 비교·견적**, **렌탈·인터넷·보험** 페이지
- **테마 페이지 영상 히어로**: 여러 테마 페이지가 쓰는 공용 컴포넌트
- **카카오톡 공유**: 투표 카드를 피드 메시지로 보내고, 실패하면 `navigator.share` → 클립보드 순서로 대체
- **계측**: 메타 픽셀 Lead, GA4·Clarity·네이버 분석, UTM·referrer 수집 → 전산 매체 분류

## 기술적으로 고민한 점

### 1. 정적 내보내기와 랜딩 페이지의 공존
서버 없이 S3 + CloudFront 로 서비스하려고 `output: 'export'` 를 썼습니다. 요청 시점 렌더링이 없으므로 랜딩 경로는 카테고리별 정적 경로 11개(`/travel/lp/<slug>/`)로 빌드 때 미리 만듭니다.
상담 접수처럼 서버가 필요한 동작은 전산 백엔드의 플랜잇 API 로 넘겨, 사이트 자체는 정적 파일로만 유지합니다.

### 2. 메타 픽셀 Lead 중복 제거
Lead 이벤트는 광고 최적화의 학습 신호입니다. 버튼을 누른 시점이 아니라 서버가 접수 성공을 응답한 뒤에만 한 번 보내고, eventID 를 함께 보내 같은 접수가 두 번 집계되지 않게 했습니다.

### 3. 카카오 SDK 초기화 순서와 폴백
카카오 JS SDK 는 외부 스크립트라 로드가 끝나기 전에 공유 버튼이 눌릴 수 있습니다. SDK 로드 → 초기화 → 공유 호출 순서를 지키고, SDK 를 쓸 수 없는 환경에서는 `navigator.share`, 그것도 없으면 클립보드 복사로 이어지게 했습니다.

### 4. 빌드 변수로 분석 ID 주입, dev 제외
픽셀·GA4·Clarity·네이버 분석 ID 는 코드에 적지 않고 빌드 변수로 주입합니다. dev 빌드에서는 분석 스크립트를 넣지 않는 규칙을 둬 테스트 트래픽이 운영 데이터에 섞이지 않게 했습니다.

### 5. 시안과 픽셀 단위로 맞추는 검증
피그마 MCP 로 시안의 수치를 읽어 옮긴 뒤, 헤드리스 Chrome 으로 1440·390 화면을 캡처해 같은 폭의 시안과 구간별로 비교합니다. 어긋난 구간을 찾아 고치고 다시 캡처하는 과정을 반복합니다.

### 6. 공유 링크로 그대로 다시 여는 계산 결과
월 납부금 플로우는 한 페이지 안에서 01~04 단계를 바꿔 그리지만, 지금 단계와 고른 값(여행지·인원·시기)을 주소의 쿼리에 함께 담습니다.
그래서 03 결과 화면을 카카오톡으로 보내면 받은 사람도 같은 결과 화면을 바로 엽니다. 여행지별 1인 월 금액은 여행 목록과 같은 상품 데이터·계산을 써서 페이지마다 숫자가 어긋나지 않게 했습니다.

### 7. 정적 사이트에서 새 견적번호 열기
사이트가 정적 파일이라, 어드민에서 새로 발급한 번호에는 그 번호의 일정표 파일이 없습니다. 그래서 새 번호의 고객 링크를 공용 화면 하나로 모으고, 그 화면이 주소에서 번호를 읽어 서버에 저장된 일정 스냅샷을 불러오게 했습니다.
고객에게 보내는 주소는 `/q/번호` 로 줄이고, CloudFront 함수가 이 요청에 공용 화면을 돌려줍니다. 운영에는 CloudFront 함수 변경을 먼저 적용한 뒤 사이트를 승격합니다. 순서가 바뀌면 그 사이에 복사한 `/q/` 링크가 404 가 되기 때문입니다.

### 8. 발급 전에 보는 미리보기
미리보기는 번호 발급 때와 같은 함수로 스냅샷을 만들어 브라우저 `localStorage` 에 담고, 새 탭의 고객 화면이 서버 대신 그 값을 같은 정규화로 그립니다. 그래서 미리보기와 실제 고객 화면이 어긋나지 않습니다.
어드민에서 다시 누르면 `storage` 이벤트로 열린 탭이 새로고침 없이 바뀌고, 맨 위 배너에 저장되지 않은 화면이라는 점과 발급 전 점검에 걸린 항목을 보여 줍니다. 주소에 번호가 있는 고객 링크는 미리보기로 열리지 않습니다.

### 9. 로그인 콜백 값이 분석 도구로 새지 않게
소셜 로그인 콜백 주소에는 1회용 `code`·`state` 가 붙어 옵니다. 네이버 분석 스크립트는 React 보다 먼저 현재 주소를 보내므로, 루트 레이아웃 `<head>` 맨 앞의 인라인 스크립트가 콜백 페이지에서만 이 값을 주소창에서 먼저 지웁니다.
콜백 교환은 한 문서에서 한 번만 해서, 개발 모드에서 effect 가 두 번 돌아도 1회용 state 로 보낸 두 번째 요청이 실패하지 않게 했습니다.
